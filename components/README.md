# App surfaces

The projector's map uses viewport pixels. Its HUD and QR use `StageBox` and a single 1920x1080 coordinate system; /map keeps the box 1920 wide and stretches it to the window's height. Each scene places the QR (`qr.placement` in `shared/scenes.ts`): large and centered on S7 until the 3 · 2 · 1 countdown, top right in the corner on L1, and hidden everywhere else, L3 and L9 included. The QR and link always encode the production `/scan` URL, which keeps working while Writing is ON. Every card displays the full host and path on one line. The stage shows no logo or data source; the "?" card does. The corner card is 424x216; right-side panels start at y276.

There is no code to type and nothing to wait for. Opening `/scan` asks the writer nothing. "Write my entity" sends one `POST /api/submit?wait=1` without a session code; the writer puts the entity in the running session and answers once its block is in. With no session running the phone says "Not open yet. Try again in a moment."; /map starts a session when it opens, and Reset starts a new one. The phone offers seven fixed colors and is dark only, whatever the system theme.

Phones never call an RPC and make no request after the submit. The name is lower-cased as it is typed. The countdown runs on the phone's own clock from the lifetime the person chose, so it can't see a Lifetime Extension: at zero it says the entity has expired unless someone extended it. "No expiration" (under the lifetime slider) writes with `ExpirationTime.permanent()`; the phone then shows `$expiresAt = 2**64 − 1` and no countdown. The real expiration and any extension show on /map. Phone error messages use fixed copy chosen by error code.

`lib/data/source-mode.ts` exports `isMockSource(mode, writerUrl?)` and `useIsMock()` for the stage and deck. Auto uses the mock only when the writer URL is absent; explicit Mock/Live selections override Auto. `useLiveData` and JoinQR consume this same rule.

`lib/stage/choreography.ts` owns scene and reveal state. L3 opens the filter bar (`Filters.tsx`) with no filter: the presenter types a name (starts with), picks a color from the list or types a country, and a country flies the camera there (`lib/map/country-view.ts`). Clearing it flies back to the whole globe. Filters match lower case. Choosing an inspection example performs no chain write.

The query panel displays `QueryRun.description` on L3: the scope first, then one predicate per line joined by AND, with the filter lines marked. It never scrolls at 1920x1080 and never shows `$creator` or `createdBy`, although every read still scopes by it. The entity card (`Inspector.tsx`) lists the attributes the phone put in (name, color, country) in one name / type / value table, then a … row that shows the ones the app adds, with `$key`, `$owner` and `$expiresAt` beside it. Its actions are Extend | Transfer | Delete | ↗ (the data explorer, in a new tab); in Transfer, "0x" then Space fills in a random checksummed wallet. Extend is off for an entity with no expiration; Transfer and Delete are off once another wallet owns the entity. The chain actions run in `lib/data/stage-effects.ts`.

The dot canvas stays mounted in every scene, so phones that write early show up at once. The bundled map style is in `lib/map/arkiv-night.json`; country borders retain its disputed-boundary exclusion. Entity disappearance remains query-driven. Long-lived businesses display their opening hours instead of a participant countdown. Dashed business pins identify app-side presentation data.

`/map` runs the whole talk on one screen: live scenes show the globe and HUD, slide scenes cross-fade the slide over the globe (`MapFrame` in `StageFrame.tsx`), and expired dots stay grey and unclickable. `/map` is the leader and `/slides` the follower over the `arkiv-mumbai-stage` BroadcastChannel: either window's keys move both, and /slides runs on its own when no /map is open. `components/stage/Presenter.tsx` holds the password gate, the two-click Reset and /map's session sync. The login (`lib/data/presenter-auth.ts`) sits in localStorage, so one password unlocks both windows. The data source selector and the read status ("Updated · block #N") live in the map's "?" card.

Verification uses the shared/app unit tests, `tests/ui-layout.mjs`, `tests/phone-ticket.mjs`, and `scripts/stage-shots.mjs`. The browser scripts serve the exact static `out/` build in an isolated context and send no chain writes. Phone-ticket fixtures cover 375/360/390 in both themes, reject any attempted RPC, and check a quiet page load, the not-open and error answers, one request per write, the local countdown to zero and the queued answer. Stage screenshots use mock data; layout checks briefly select public live reads for the presenter to verify source synchronization. Inspect the relevant PNGs before accepting a visual change.
